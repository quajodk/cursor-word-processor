docx export splice

done

Edit the original zip rather than regenerate it

verifiedFull corpus, 288 real Word documents (177 MB): T0 100% byte-identical, T1 286/286 surgical — exactly one paragraph changes, nothing else moves. Pandoc on the same files: T0 0%, T1 0.0024, T2 0.318; it zeroes tables, comments and revisions and scores 0.03 on numbering.

biggest gapThe rebuilt paragraph is regenerated whole rather than run-spliced (runSpliced is 0 everywhere), so the finer-grained path that reuses each run’s rPr is written but never exercised. Formatting survives anyway — verified 59/59 — but the cheaper path is untested.

Decisions on the record

Editor engine

ProseMirror, used directly — not Tiptap, not Lexical

Pure decorations are load-bearing for AI diffs, diagnostics and blame. Lexical and Quill lack them; Tiptap's auto-schema fights the OOXML mapping.

The docx tension

Splice the original zip; never regenerate it

Turns 'how much OOXML can we model?' into 'how little must we touch?'. An unedited round-trip is byte-identical, and fidelity degrades only in proportion to what was actually edited.

Anchors

Exact in-session, fuzzy only for externally-edited files

While the doc is open we observed every change, so identity needs no guessing. Sequence alignment is reserved for files edited by another tool — that split is what makes the problem tractable.

Confidence floor

Drop formatting rather than risk misapplying it

A dropped style is a visible bug the writer can fix; a misapplied one silently corrupts a document they trusted.

Diagnostics

harper.js in a worker, behind an LSP-shaped seam

Offline, Apache-2.0, works unchanged in web v1 and Tauri v2. The LSP shape makes adding a second checker cheap.

Perf honesty

A measurement that covers only part of a path may fail a budget but may never certify a pass

A headless process cannot see the DOM half of a keystroke. Reporting it as 'pass' would manufacture confidence in a number that never measured the thing it names.

Scoring honesty

A tier entailed by another tier is labelled, not counted twice

Scriv’s T2 is 1.0000 because T0 is 100% — T2 scores the zero-edit round trip that T0 already proved byte-identical. Presenting both as achievements would inflate one fact into two.

Measuring a budget

A budget that names a size needs an upper bound on the band, and warm-up is reported separately rather than folded in

“50-page” measured as “≥500 paragraphs” swept in 11,000-paragraph documents and reported a failure three times the real one; a bench with no warm-up puts JIT cost in the p99 tail and blames the code for it.

Key bindings

Verified by pressing them in the running app, not by reading a table

Mod-Ctrl-ArrowUp looked ideal for expand-selection and is silently eaten by Mission Control on macOS. The keys the OS takes are now listed in the binding table so they are not rediscovered.

Notes

  • Two bugs in the selection ladder were found by testing rather than reading: it walked back down once a selection spanned two paragraphs, and selecting the whole document used a position that sits between nodes rather than inside text. Both are now asserted by tests.
  • The perf gate went from red to green through three changes, only one of which was an optimisation: discarding warm-up (3352→2364 ms), bounding the 50-page band so it stopped including 500-page documents (→1260 ms), and removing per-part hashing that nothing read (→670 ms).
  • A check of mine reported three documents losing right-to-left run formatting. Reading the XML showed the opposite: the exporter had dropped a second, completely empty run carrying only that property and no text, which is correct. The comparison was wrong, not the exporter — it compared whole property payloads, which cannot tell a legitimate run merge from a real loss. It now compares property names, and that invariant is enforced by a test.
  • The splice design is validated: on real Word documents an unedited round trip is byte-identical, and a one-word edit changes exactly one paragraph. Pandoc, which regenerates, scores 0% on both — while remaining self-consistent at 0.9913 against its own output, so this is not a strawman: it preserves its own conversion faithfully, just not the user's document.
  • The gate is currently RED, deliberately and correctly: importing large Word documents takes p99 3.35s against a 1.2s budget. A 84ms average across the whole corpus had hidden this — the large documents are the bottleneck.
  • A status-bar reading that looked like two bugs turned out to be the 220 ms coalescing timer doing its job — the status store deliberately keeps typing off React’s render path. Verified by measurement rather than patched on suspicion.
  • Both session interruptions cost roughly a wave each. Builders now commit after every deliverable, which is why nothing was lost the second time.
  • The .docx corpus is public real-world documents. The 59 .docx files in ~/Downloads are personal and are deliberately not used.
