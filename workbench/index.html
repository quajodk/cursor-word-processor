Subsystems

Document model & block identity

done

ProseMirror schema shaped like OOXML; stable anchors that ride transactions

verified5/5 identity tests pass: typing preserves anchors, split keeps identity on the first half, paste de-duplicates, delete is clean

biggest gapNot yet exercised against a real .docx-derived document.

App shell & host seam

donedone

React chrome, ProseMirror surface, bun server implementing HostApi

verifiedThe app runs. Real .md opened from disk, edited and saved back correctly — frontmatter, GFM table, ordered list, bold, em-dash, CJK and ± all survived. Live status bar reads 2.7 ms p99 keystroke latency in a real browser, including ProseMirror’s DOM write, against an 8 ms budget.

biggest gapThe presentation layer was built four times. A coherence pass driving the running app found two keyboard systems racing — a capture-phase window listener that preventDefaults before ProseMirror's plugins ever see the key, so the completion popup cannot be dismissed with Escape and two full implementations of ⌘K sit dead. Three panels share one slot with three focus policies and two words for “close”. Opening the comments pane scrolls the tab strip out of the window. None of it needs an algorithm rethought; all of it is apps/web.

Markdown ⇄ model

donedone

CommonMark + GFM + CriticMarkup, round-trip stability

verifiedLink hrefs lost across 1,437 real documents: 4, all CommonMark spec cases with backslash escapes inside URLs. Images are inline nodes, so a linked badge keeps its href and a mid-sentence image no longer splits its paragraph.

biggest gapA no-op save still rewrites 64% of lines across the corpus — mostly escaping of “_” and “*”, which cannot be narrowed without risking a change to what reparses as emphasis.

docx import, sidecar & anchors

donedone

Offset-recording XML index, fidelity sidecar, alignment-based re-anchoring

verified288/288 real Word documents import; mean text recovery 99.49%. The re-anchoring engine — 925 lines of constrained Needleman–Wunsch, what the design calls “the actual research problem” — now has a test, and it found a traceback bug worth ~40 points of recall on every position-changing edit. Across 12 documents and ~5,600 blocks per scenario: reword, rewrite, split, merge, insert and delete all recover 100%; a moved section 95.7%; a week of every kind of edit at once 93.8%. Reproducible run to run.

biggest gapMoves are the honest limit: a move is not expressible in an order-preserving alignment, so it is recovered afterwards by exact content match, which a block that was moved AND reworded defeats. Those 239 blocks are lost and ledgered, never guessed at. Text inside text boxes and content controls is still dropped.

Agent mode

done

An instruction that edits the whole workspace, reviewed site by site before it lands

verifiedVerified end to end in the running app on 1,492 files. Edits the file at byte offsets rather than regenerating it, so a one-word rename is a one-word diff. Sites flagged uncertain start rejected; the apply re-reads every file and skips sites that moved during review. 18 tests against 120 real corpus documents.

Decisions on the record

Editor engine

ProseMirror, used directly — not Tiptap, not Lexical

Pure decorations are load-bearing for AI diffs, diagnostics and blame. Lexical and Quill lack them; Tiptap's auto-schema fights the OOXML mapping.

The docx tension

Splice the original zip; never regenerate it

Turns 'how much OOXML can we model?' into 'how little must we touch?'. An unedited round-trip is byte-identical, and fidelity degrades only in proportion to what was actually edited.

Anchors

Exact in-session, fuzzy only for externally-edited files

While the doc is open we observed every change, so identity needs no guessing. Sequence alignment is reserved for files edited by another tool — that split is what makes the problem tractable.

Confidence floor

Drop formatting rather than risk misapplying it

A dropped style is a visible bug the writer can fix; a misapplied one silently corrupts a document they trusted.

Diagnostics

harper.js in a worker, behind an LSP-shaped seam

Offline, Apache-2.0, works unchanged in web v1 and Tauri v2. The LSP shape makes adding a second checker cheap.

Perf honesty

A measurement that covers only part of a path may fail a budget but may never certify a pass

A headless process cannot see the DOM half of a keystroke. Reporting it as 'pass' would manufacture confidence in a number that never measured the thing it names.

Scoring honesty

A tier entailed by another tier is labelled, not counted twice

Scriv’s T2 is 1.0000 because T0 is 100% — T2 scores the zero-edit round trip that T0 already proved byte-identical. Presenting both as achievements would inflate one fact into two.

Measuring a budget

A budget that names a size needs an upper bound on the band, and warm-up is reported separately rather than folded in

“50-page” measured as “≥500 paragraphs” swept in 11,000-paragraph documents and reported a failure three times the real one; a bench with no warm-up puts JIT cost in the p99 tail and blames the code for it.

Key bindings

Verified by pressing them in the running app, not by reading a table

Mod-Ctrl-ArrowUp looked ideal for expand-selection and is silently eaten by Mission Control on macOS. The keys the OS takes are now listed in the binding table so they are not rediscovered.

Typecheck graph

Every package is a referenced project, not just the ones that happened to be listed

Four packages including the largest were outside the root tsconfig references, so every clean typecheck was checking a subset. Adding them surfaced 114 errors, three of which were real defects.

Completion restraint

The popup never opens on a bare word, at any length

Every threshold low enough to be useful is low enough to interrupt an ordinary sentence. Code completion can fire on every identifier character because a programmer is always naming something; a writer usually is not.

Perf gating

The gate will not fail on a percentile its own sample size cannot support

docx throughput measured 1.299, 1.841 and 2.281 ms across three runs of identical code. With 227 samples a p99 rests on about three order statistics. A gate that fails at random teaches people to re-run until it passes.

AI suggestions

Rendered with the schema’s existing tracked-change marks, not a parallel mechanism

Accepting an AI rewrite and accepting a colleague’s tracked change become one code path, an AI suggestion exports to Word as a real revision, and undo and position mapping already understand it.

Diagnostics

Squiggles are decorations, and the checker declines languages it cannot handle

A squiggle in the document would be savable, undoable and exportable to Word. And running an English checker over Hindi produces a wall of false errors, which is worse than no diagnostics at all.

Prose git

A newline inside a block is a soft wrap, not a sentence boundary

Treating it as one made reflowing a paragraph produce a diff — defeating the entire purpose — and hid every mixed-authorship sentence from blame, since each fragment sat on its own line.

Multi-cursor

The primary cursor stays a real selection; extra cursors are plugin state drawn as decorations

A Selection subclass holding N ranges is the “proper” answer and breaks everything downstream — the view draws one native selection, and baseKeymap, input rules and mark logic all read the primary range.

Images

Inline, not block

Markdown’s linked badge is a link wrapping an image and OOXML’s drawing sits inside a run. Modelling images as blocks forced every in-paragraph image to split it, and the enclosing link mark had nowhere to live — so saving a file deleted the hyperlink.

Palette

Derived from the binding table, not maintained beside it

Thirty text operations had a key and no palette entry, and two of them were bound to chords macOS eats — so they could not be invoked at all. Deriving the palette from the table means a binding cannot exist without being discoverable.

Two kinds of failure

Losing a match and misapplying one are counted separately and held to different standards

They are not the same size of mistake. A lost anchor loses formatting visibly, says so in the ledger, and the writer can fix it. A misapplied one hands one paragraph another's properties and says nothing. A single “accuracy” number would let the second hide inside the first.

Document order

Never read it from an object's key order

Block ids are random per import and about 1% come out looking like integers, which JavaScript hoists to the front. The alignment engine was being scored against documents whose paragraphs had been shuffled, with numbers that drifted between runs.

Safety nets and measurement

Measure each layer with the layer beneath it switched off

A recovery pass that runs after the aligner made a broken aligner look like a merely underperforming one at 61%. With it disabled the real figure was 10%, and the cause was findable in an afternoon.

Coherence

One fresh agent per wave reconciles the pieces, driving the app rather than reading it

Features built independently pass their own tests and still add up to four products. This pass found the model layer coherent and the presentation layer built four times over — a class of defect no feature's own test suite can see, because every one of them is individually correct.

Notes

  • The coherence pass finally ran, after two earlier attempts died on a rate limit and a network error. Its verdict: scriv is not four features in a trench coat at the model layer — it is one tool whose presentation layer was built four times. Nearly every finding is in apps/web.
  • Two keyboard systems race and the window always wins. The command registry installs a capture-phase listener that calls preventDefault and stopPropagation before ProseMirror's plugin handlers run on bubble, so any key in both systems belongs to the registry. Observed live: with the completion popup open, ArrowDown reaches the editor and Escape does not — the popup cannot be dismissed. Four in-editor handlers are dead code, including two complete implementations of ⌘K, one commented as beating the command keymap. Three comments in one file each name a different plugin as the owner of Escape.
  • The git pillar is outside the command system entirely: a hand-rolled window keydown in App.tsx. Verified against the live palette — there is no diff, blame, git or changes entry in it. It is also invisible to the binding-collision test, which reads the command table from source.
  • Open a .docx and the changes pane is a silent empty box: its whole live text is “Changes / Blame / esc”, because the text accessor returns null for binary codecs. The pane carries three carefully written explanations for other dead ends and none for the one where the git feature meets the docx feature.
  • This page was carrying a false claim until the coherence pass caught it: the app shell's biggest gap still read “opening a .docx is not possible yet”, while a note further down the same page said a Word document opens, edits and saves through the UI. Both were published together.
  • The alignment engine had no test at all — 925 lines of constrained Needleman–Wunsch, and beside it a 239-line ground-truth harness built for exactly this purpose that was imported by nothing. The expensive half of making it checkable had already been done and never used.
  • Its first measurement found the bug. The traceback decided whether a gap had been opened or extended by testing a Float32 cell for equality within 1e-6, on a matrix whose values reach several hundred where one ulp is ~6e-5 — sixty times coarser than the tolerance. The test could not come out true, so a traceback that entered a gap never left it. One five-paragraph insertion 66 blocks from the end turned the rest of the walk into 5,382 consecutive inserts and ran the column index to -4758; every earlier anchor was reported lost.
  • The alignment itself was never wrong. Instrumented on a 669-block document, the optimum score is reached along the true path, with true-pair similarity at p50 0.981 and displacement well inside the band. Every match was there to be taken. Only the walk back was broken — which is why the symptom looked like a scoring problem and stayed unexplained for a wave.
  • A test that cannot fail is not a test, so each new one was run against the old code first. The aligner test turns 4 of its 7 red, including the mirror-image defect on deletions at “20.3%, 240 lost”. The block-order test binds a comment to “Fourth paragraph.” instead of “First paragraph.”
  • Two numbers in this project's own bug report were wrong, both from measuring a 12-document sample instead of the corpus. Integer-like block ids are 0.94%, not 0.07% — one block in a hundred, not one in 1,500. And the comment-binding bug it described is latent rather than active: it needs one comment anchor in two blocks, which happens zero times across all 288 documents. The fix is still right; the report overstated what it was fixing.
  • Measurements taken while files are being edited are not measurements. Two corpus runs disagreed — 5,406 blocks against 5,405 — and both were contaminated by edits landing mid-run. Sorting document order out made three consecutive clean runs byte-identical, which is the only reason the numbers on this page can be quoted.
  • This page was rendering a failing tile green. Budget direction was inferred from the unit, so for a count where fewer is better the comparison ran backwards: 4 link targets lost against a budget of 0 read as a pass. build.ts's own comment says a progress page that shows green while the gate is failing is worse than no page.
  • Four test files were passing with zero assertions when the corpus is absent — and the corpus is gitignored, so that is the state of a fresh clone. The worst had a guard that read `expect(true).toBe(true)`, in the one file that checks the byte-identity targets. New tests for the aligner and for block order need no corpus at all.
  • Theme cycling was dead. `view.cycleTheme` and `table.insert` were both on ⌘⌥T, the later registration wins, and `table.insert` is live whenever the caret is in the document — so the binding did nothing exactly when anyone would use it. I introduced it myself, moving the theme off another chord. The whole binding table is now read by a test that fails on any collision.
  • Heading numbering is built and deliberately not shown. 37 corpus documents auto-number their headings and none of it reached the editor; the engine scores 57.2% against the numbers Word itself cached in 14 documents' tables of contents, up from 5.3% once numbering was read off the paragraph style rather than the paragraph. A wrong section number is worse than a missing one, so it stays dark until that number is much higher.
  • Agent mode's rename needs no model, and that is the design rather than a limitation. Word boundaries, plurals, possessives, case and "never touch code" are all decidable; deciding them exactly is more useful than asking a model to guess, and it means the feature works with the network unplugged.
  • The rename's own test caught the bug that would have destroyed a workspace: `classify` extends a site to carry a plural but returned only the term's end, so `to` sat one suffix short of `before` — every carried site would have written "settingss" over "configurations".
  • The keystroke→paint harness was complete, well-designed, and imported by nothing — a whole subsystem with a row in the report and no caller. Wired up, it failed: 17.0 ms against a 16 ms budget. And the gate would not act on it, because 240 samples put only 3 behind the p99. A budget that can never fail is not a budget.
  • ProseMirror renders every block; CodeMirror-based editors virtualize the viewport. That is the bill for the tree model that makes decorations and the docx mapping tractable. `content-visibility: auto` is the browser's own version of that virtualization — p50 11.09 → 6.00 ms — and the obvious risk, that it makes jumping to the end of a long document expensive, was measured both ways and is not real.
  • spliceZip was eating its own input. `buf.slice(...)` on a Node Buffer is the legacy alias for `subarray` and yields a VIEW, so patching the central directory wrote straight back into the caller's bytes. The exported package was always correct and the ORIGIN was destroyed. Invisible with a plain Uint8Array, where `.slice()` copies — which is exactly why it survived.
  • The importer hard-coded `resolved: false, parentAnchorId: null` and never opened commentsExtended.xml. Every reply in every document would have read as a separate top-level thread. The corpus hid it completely: 675 threads across 11 documents, and not one carries a reply or a resolution.
  • The global key dispatcher listens in the capture phase on window, so it saw every key before any text field did: ⌘⏎ in the comment reply box ran “Exit code block”, and ⌘B in the search field toggled bold in the document behind it.
  • OffsetMap was wrong and a new test caught it. It emitted a separator for every BLOCK; textBetween emits one only before a TEXTBLOCK. A bullet list with four items is nine blocks and four textblocks — so in any document containing a list, every diagnostic, every AI hunk and every extra cursor after the first list landed on the wrong word. Nothing threw.
  • The incremental linter was expected to match a whole-document lint exactly. On real prose it does not — 4 diagnostics in 200 — and the difference runs the other way: Harper does not treat a bare newline as a sentence end, so the joined document merged two speakers' dialogue into one '52-word sentence' warning while hiding three real findings inside the paragraphs it had glued together.
  • Making images render broke the splice engine — T0 fell from 60/60 byte-identical to 54/60 — and the assertion added an hour earlier caught it. That is what a gate is for.
  • An independent audit found two of four house rules violated, a security defect, and the headline fidelity metric ungated. It was right on all three. The worst: saving an unedited Markdown file was DELETING hyperlinks from CI badges — silent data loss in the layer this project calls the source of truth. I had seen the symptom myself, filed it as a pre-existing limitation, and moved on.
  • Move detection had never fired: the longest-increasing-subsequence used each pair's index in the array as its value, which is increasing by construction, so every pair was always kept and nothing was ever reported as moved.
  • The blind comparison still cannot be run here: it needs the same task performed in Cursor, Google Docs and Obsidian by an operator. It also now needs a starting document — checked against the project's own spec, 0 of 288 corpus files meet all five of its requirements at once.
  • The .docx corpus is public real-world documents. The 59 .docx files in ~/Downloads are personal and are deliberately not used.
Every number on this page is measured or absent. Nothing here is estimated.
